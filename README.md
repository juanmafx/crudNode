# node-crud-api

A small, dependency-free CRUD REST API for items, built only on the Node.js standard library.

> **Project history:** originally created in 2020, modernized in 2026. The 2020 repository contained only a `.gitignore`, so the entire implementation was added in 2026.

## Purpose

crudNode implements the four persistence operations (create, read, update, delete) over HTTP for one resource, an `item` with a name and a description.

## Why this project exists

The 2020 repository held only a Node.js `.gitignore`, so its original intent is known only from its name. This version implements that name and shows how a deliberately small service can still have clear module boundaries, strict input handling, safe persistence, and automated tests, without a framework or third-party runtime packages.

## What it does

- Exposes a versioned JSON API under `/api/v1/items`, plus an unauthenticated `/health` check.
- Requires a bearer token for every item operation.
- Validates all input and rejects unknown fields.
- Stores items in a local JSON file using atomic, serialized writes.
- Applies per-address rate limits to item routes (IPv6 clients are grouped by /64), body size limits, a connection cap, server timeouts, and security headers on application responses.

It has no user accounts, no web interface, and no multi-instance support. See [Limitations](#limitations).

## Architecture

```text
HTTP request
    |
src/http            routing, authentication, rate limiting, body parsing, responses
    |
src/domain/items    validation and business rules
    |
src/infrastructure  serialized repository and atomic JSON file storage
```

The full design is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Quick start

Requires Node.js 22 or later. The test suite was run on Node.js 22.22.3 and 24.22.0. There are no packages to install.

```bash
git clone https://github.com/juanmafx/crudNode.git
cd node-crud-api
export API_TOKEN="$(node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))")"
npm start
```

The server listens on `http://127.0.0.1:3000`.

## Usage guide

```bash
BASE=http://127.0.0.1:3000/api/v1/items

curl -i -X POST "$BASE" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Notebook","description":"A5, dotted"}'

curl "$BASE?limit=20&offset=0" -H "Authorization: Bearer $API_TOKEN"

curl "$BASE/<id>" -H "Authorization: Bearer $API_TOKEN"

curl -X PATCH "$BASE/<id>" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"description":"A4, lined"}'

curl -X DELETE "$BASE/<id>" -H "Authorization: Bearer $API_TOKEN"
```

### Endpoints

| Method | Path | Success | Description |
| --- | --- | --- | --- |
| `GET` | `/health` | `200` | Liveness check, no authentication |
| `GET` | `/api/v1/items` | `200` | List items (`limit` 1-100, default 20; `offset`, default 0) |
| `POST` | `/api/v1/items` | `201` | Create an item |
| `GET` | `/api/v1/items/{id}` | `200` | Read one item |
| `PATCH` | `/api/v1/items/{id}` | `200` | Update `name`, `description`, or both |
| `DELETE` | `/api/v1/items/{id}` | `204` | Delete an item |

### Item fields

| Field | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Generated by the server |
| `name` | string | Required, trimmed, 1-120 characters, no control characters |
| `description` | string | Optional, up to 2000 characters; line breaks and tabs allowed |
| `createdAt` | ISO 8601 | Set by the server |
| `updatedAt` | ISO 8601 | Set by the server |

Errors share one shape:

```json
{ "error": { "code": "validation_failed", "message": "The request is invalid.", "details": [] } }
```

## Configuration

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `API_TOKEN` | Yes | None | Bearer token, at least 32 characters. The server refuses to start without it. |
| `HOST` | No | `127.0.0.1` | Bind address |
| `PORT` | No | `3000` | Bind port |
| `DATA_FILE` | No | `data/items.json` | Storage path; `data/` is gitignored |

See [.env.example](.env.example). The application does not load `.env` files on its own.

## Database schema

The runtime stores data in a JSON file. [db/schema.sql](db/schema.sql) is an **optional** SQLite schema (3.37+) that mirrors the item model for anyone moving to SQL. The application does not read or write it; the test suite only verifies that it applies and enforces its constraints.

```bash
sqlite3 crud.db < db/schema.sql
```

## Testing

```bash
npm test
npm run test:report
```

Tests use the built-in `node:test` runner and cover validation, persistence, security primitives, and the HTTP API over a real loopback socket. The schema tests need the `sqlite3` CLI and are skipped if it is missing. The committed output of an actual run on Node.js 24.22.0 is in [reports/tests/test-report.txt](reports/tests/test-report.txt).

## Security notes

- Bearer tokens are compared in constant time over SHA-256 digests.
- The server binds to loopback by default and has no TLS. Put a TLS-terminating reverse proxy in front of it before exposing it.
- Behind a proxy, all clients share one rate-limit bucket because forwarded headers are deliberately not trusted.
- The API has no cookies or browser sessions and sends no CORS headers.
- There are no user accounts or passwords, so two-factor authentication and password hashing do not apply.
- Requests the Node.js HTTP parser rejects receive its plain default error response, without the security headers.

See [SECURITY.md](SECURITY.md) and [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md).

## Limitations

- One shared token, with no per-user identity or roles.
- A single process owns the data file; running several instances against it is unsupported.
- Each write rewrites the whole file, which suits small datasets only.
- Concurrent `PATCH` requests are serialized, and the last write wins.
